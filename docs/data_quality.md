# 数据质量报告

> 数据处理阶段的摸底分析结果，作为 EDA 报告与答辩「数据质量」章节的数据来源。
> 分析代码：`outputs/eda/`（指标计算基于 `src/data.py` 的加载接口）。

## 一、规模与分布

| 数据集 | 条数 | 类别数 | 文本长度（mean / p95 / max） |
|---|---|---|---|
| train | 202,500 | 9（每类 22,500，完全均衡） | 9.0 / 12 / 19 字符 |
| dev | 10,000 | **8（缺 other_chitchat）** | 8.9 / 12 / 16 |
| test | 11,099 | 9（other_chitchat 仅 1,099 条） | 9.0 / 12 / 19 |

**发现 1：dev 集缺失闲聊类。** 生成脚本按类去重后，闲聊类（模板空间小）产出的唯一样本
不足以覆盖 22,500+1,250+1,250 的配额，dev 分到 0 条。后果：训练过程中 dev_acc
从未覆盖闲聊类的识别能力，模型选择对这一类是盲的。

## 二、标注冲突（核心发现）

### 2.1 训练集内冲突：1,266 种文本

同一文本以不同标签重复出现，且 1,266 种**全部**为跨类冲突。原因：生成脚本的
短语库存在跨类重复（如「保密协议」同时出现在 legal_contract 与 hr_onboarding，
「陪产假/育儿假」同时出现在 policy_attendance 与 hr_onboarding）。

典型样例：

| 文本 | 冲突标签 |
|---|---|
| 哎保密协议是什么 | legal_contract / hr_onboarding |
| 加班费计算麻烦说下 | finance_expense / policy_attendance |
| 陪产假麻烦了 | policy_attendance / hr_onboarding |

完整清单见 `outputs/eda/训练集标注冲突.txt`。

### 2.2 训练/测试集间冲突：135 条

test 集中 135 条文本在训练集中出现过且标签不同（同标签泄漏为 0 条）。
这 135 条模型无论怎么答都必错一边，直接压低了测试准确率上限约 1.2%。
清单见 `outputs/eda/训练测试冲突.txt`。

## 三、对已有实验结论的影响

- 基线模型 test_acc=98.43% 是在含冲突的数据上得到的，仍大致可信（冲突占比仅 0.6%），
  但 dev/test 的类别覆盖不全需在报告中声明
- 数据清洗（剔除或统一冲突标签）后重训是对照实验的合理下一步，用于量化
  「数据清洗带来的收益」

## 四、清洗建议（供优化阶段参考）

1. 训练集：同文异标的样本对全部剔除（约 2,532 条，占 1.25%），或按短语库归属统一标签
2. dev/test：剔除与训练集冲突的 135 条，保证评估公平
3. 补充闲聊类样本（模板空间小，需人工扩写或引入新模板），使 dev/test 覆盖 9 类
4. 清洗后数据另存为新文件（如 `train_clean.txt`），保留原始数据不动，保证实验可对照
