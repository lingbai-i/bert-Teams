# 答辩结论页：合成数据高分，需要真实问句验证

## 数据发现

| 证据 | 对评估的含义 |
|---|---|
| train 202,500 条，九类各 22,500 | 训练类别均衡 |
| dev 10,000 条，闲聊为 0；test 闲聊仅 1,099 条 | 验证覆盖不完整，文件条数与 README 不一致 |
| 三个划分长度中位数均为 9 字，P95 均为 12 字 | 测试以短问句为主，不能代表复杂自然表达 |
| 启发式归一化后，dev/test 核心短语均在 train 出现 | 提示模板/主题同源；不是“100% 泄漏” |
| train/test 有 135 条同文异标签，全划分有 1,557 种冲突文本 | 标签口径需要统一，不能将这些重复说成高分原因 |
| 人工集只有 18 条，缺五类且含 `out_of_scope` | 需补齐覆盖并区分九分类与拒答测试 |

## 核心结论

合成测试集衡量的是已见业务主题及相近句式下的识别能力。
模板同源可能使我们高估模型面对真实问句的能力，因此需要独立、标签一致的人工评估集。
本次 EDA 未运行模型，不能声称已测出 BERT 虚高的幅度。

## 建议行动

- 数据组核对 dev/test 缺少样本的原因，复核跨部门冲突标签。
- 全员贡献真实问句，补齐九类并扩充至 100+ 条，冻结测试集。
- 评估组分别汇报合成集与人工集指标；体系外/拒答用例单列。

## 约一分钟口述稿

“我负责数据探索与质量分析。训练集二十万余条，九类完全均衡，但验证集实际缺少闲聊类，
所以目前不能用它证明完整的九分类效果。三个划分的问句中位数都是九个字符，
去掉常见开场语和结尾后，验证和测试中的核心短语都能在训练中找到，说明测试比较依赖相似主题和模板。
同时，我发现一百三十五条训练与测试重复文本的标签全部冲突，因此不能把这些重复直接解释成分数升高。
我们的结论是：合成数据高分需要真实问句验证。目前人工集只有十八条，还要补齐类别、统一标签，
再用同一模型比较合成集和人工集表现。EDA 提供风险证据，不代替实际模型评估。”
